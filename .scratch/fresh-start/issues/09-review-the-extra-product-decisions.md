# Review the extra product decisions

Type: grilling
Status: resolved
Blocked by: 01

## Question

Which of the 9 further product decisions in the old scope document (listed at
the end of [old-rulings.md](../research/old-rulings.md)) carry forward as
decision records, beside the six already kept?

Several were already settled in the rulings reviews (marks passed up, slave cap
warns, no made-up numbers, player rolls lost dice, editing is a correction,
no monitor maximums in the log); don't re-ask those. The Matrix review left
"announce before moving an icon's children" here, as part of the "tell before
changing the GM's data" principle.

Includes whether limits default to warning or refusing, now that the old
"warn rather than refuse" default was dropped.

## Answer

Decided with Xavier, 2026-09-28.

**New product decisions (5):**
1. **The app changes the GM's data only after saying so.** First example:
   changing an icon's type announces "N icons will move to the top level"
   before Save.
2. **Enforcing a rule: warn by default; refuse only where Xavier has said
   so.** Refusals so far: Seize before rolling; skipping someone who hasn't
   rolled; files placed only on commlinks, decks and hosts. The slave cap
   warns.
3. **Rules must be right wherever the app does the maths.** This covers
   Initiative Score decrements, wound modifiers, mark caps, IC Initiative and
   the like. How tests are resolved isn't the app's job, and finding a rule
   doesn't mean building it.
4. **Only a player's first character gets the Initiative roll prompt**; others
   are rolled by the GM. This is how things stand today.
5. **In a future Matrix player view, a player sees only their own marks.**
   Widening it goes through the rules look-up first.

**Folded into "tracker, not a referee":** Matrix noise is a GM-set reminder
and is never taken off any dice pool. Out of scope: modelling a subsystem's
whole decision tree.

**Already settled elsewhere:** marks passed up; the slave cap.

**Dropped:** "split big requests into small features" (the `/to-tickets`
command does this).

**New to-do item for the switch:** prompt for every character a player
controls.
